Agent-memory 是帮手还是污染源？

Dynamics-memory 项目的文献调研可视化汇总。答案：这正是 2025-2026 年主战场——"有记忆更差"已被多篇独立工作证实，失败被定位到五层独立机制；记忆服务的主体拆成四类；第五轮把 context 工程 × memory 工程的协作界面读了出来：窗口是 L1 cache，记忆是 L4——中间隔着驻留/驱逐/写回三张契约。

核心问题：引入 agent-memory 后，LLM 在长任务上的回答/行动是变准了，还是被污染变差了？

03 — FOUR SUBJECTS

记忆服务的主体，不是一个，是四个

第四轮按"记忆内容是谁"重排文献：四类主体的失效物理、生命周期语义、攻击面各不相同。我们当前架构主要覆盖第一类。

S·01 世界事实

外部状态与声明值

TEPA / STALE / Supersede。失效=过时、被撤回。生命周期可"作废"（supersede/withdraw）。我们覆盖的主体。

S·02 用户画像

属性 / 习惯 / 偏好

DynamicMem / PersonaMem-v2。偏好从不明说，须从分散行为推断；三种时间尺度漂移；前沿模型隐式识别仅 37–48%。来源授权句法对此覆盖为零。

S·03 关系状态

谁说、对谁说、共同约定

GroupMemBench。同一句话不同人说→不同更新；最强系统仅 46%，根因是摄入管线抹掉了说话人身份。

S·04 自我履历

经验→程序、教训

MemoryGraft / Zombie / TAME。不能"撤销"只能"学到教训"；同时暴露在假经验、对抗性存续、良性漂移（misevolution）三条路上——须走最严准入。

读者侧机制底层：LLM 不做全局状态更新，只在检索时对 binding ID 做局部重映射（rebinding circuit，~3-10% 组件）；CL-Bench 显示"从 context 学习"前沿模型仅 17-24%。含义：serve 层要给出已算好的当前态，而非让模型自己重建证据。

04 — CONTEXT × MEMORY

context 工程 × memory 工程：隔着三张契约

第五轮专读界面文献。收敛结论：context window 是 L1 cache 不是 memory（857 生产会话 21.8% 结构性浪费实测）；跨会话持久记忆是 L4、"剩余前沿"。两工程的分工与契约点如下。

C·01 驻留/驱逐

谁进窗口、何时让位

Pichay 按需分页：evict 陈旧内容、模型再请求=page fault、fault 史驱动 pin（离线 fault 率 0.0254%、context −93%）。ACM：agent 自主决定压缩时机，丢弃内容无损 offload 到外部记忆——从 context 消失 ≠ 从系统消失。

C·02 写回校验

context→memory 的逆向流

Root Theorem 推论五：压缩器在被压缩的信道内运行，验证门必须外部化——compression paradox：触发太晚则压缩本身在衰减区运行。ClawVM：harness 是天然执法点，staged validated writeback 消灭 bootstrap-loss/flush-miss/destructive-writeback 三类现场故障。

C·03 可用性

relevant ≠ admissible

2610.07309：同一记录对"现在是什么"不可用、对"怎么变的"必需——可接受性是查询条件化的。可信 namespace 预筛 top-20 召回 0.432→0.533、评测工作量 −98.3%；4 读者中 1 个在相关但不可接受曝光后字面泄漏（+0.156）。新指标：inadmissible exposure 率。

ACE（2510.04618）是替代路线：把"履历/程序性记忆"当可演化 playbook 纯 context 实现，结构化增量 item 防 context collapse（+10.6% agent，无标签执行反馈）——和我们"版本化条目优于块重写"独立同解，也是 S·04 主体的竞争者。

05 — OUR GAPS

文献确认而我们未覆盖的缺口

按对"记忆是否提升最终答案"的影响排序。三个都是开放问题，不是追赶项。

GAP·01

隐式失效

"我摔断腿了"应让"骑车通勤"失效，但没有同槽改值，授权句法永远触发不了（PENDING-02）。STALE 证实这是所有路线的共同盲区，Type II 级联普降 20–40pp。

GAP·02

排空假设

25/25 全是"后台排空后查询"的分数。维护吞吐跟不上时，未消化记忆会被检索——Anatomy 的 agency tax。需要"未消化标注"或排空感知的服务降级。

GAP·03

PR 预设抵抗

用户提问自带旧态前提时，最好模型抵抗力仅 30%。serve 层应显式标注"该前提已失效"；我们还没有这类探针。LongMemEval-V2 的 premise awareness 题型可借。

06 — ACCEPTANCE PROTOCOL

从文献继承的可证伪验收协议

替代"25/25"式单分。每一条都能独立判真伪。

01TEPA 相位协议：stable / light / reversal / return 分相对 no-memory 报差；reversal 相 > no-memory 才算撤销机制兜底。
02MemDelta 单变量：每次只变一组件 + 配对检验 + 随机基线 + 写路径成本；只换 embedding 即可翻转结论。
03Stored Evidence 分解：预算耗尽 vs 预算内答错分开；rollout 不截断，预算事后判定。
04EvolveScaler 分解：选记录错 / 聚合错 / 排序错分开——聚合占 46–56% 是最大类。
05pass@k vs avg@k：分离偶尔对与稳定对；单链结果只作探索性证据。
06MemOps 操作级：Leakage Rate + Stale Value Rate + Provenance support 与答案准确率并列。
07良性代价：无冲突流量上单测服务端误拒率；同配置至少三次复跑才下结论。
08R2 同态对照：credit 归因以"同一记忆态不同操作"为比较单位，不跨分叉轨迹比。
09归因顺序：答案层失败先做记忆层反事实（去候选重答），再归因读者模型。
