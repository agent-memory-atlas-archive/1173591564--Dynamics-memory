第一幕 ·  问题

大多数 agent-memory，
在写入的那一刻就已经输了

典型管线：对话结束 → LLM 蒸馏成"记忆条目" → 存进池子 → 下次召回注入。每一环都在丢东西。

写入时取舍必错

写入时不知道未来会被问什么，只能按"通用重要性"压。而真实查询常常要的正是当时看起来不重要的那句"因为 Y"。这是结构性的，换强模型救不了。

蒸馏件没有作废标记

"决定用 X"进了池子；三天后推翻了它改成 Y。池子里 X 和 Y 并排躺着，谁作数？旧值与新候选并排端出、已作废值继续服务——项目里 N53 三链复现过这个病。

错了的也被蒸馏

助手答错的内容一样会被提炼成记忆。eval/BASELINE.md 的消融记录：去掉衰减/去重/张力三个机制，recall 反而更高——敌人在内核，不在模型。

压缩的罪不在压缩，在压缩后删原件 判据只有一条：这个加工件错了，原始信息还找得回来吗？找得回来就安全，找不回来就是单点故障。
第一幕 ·  问题

好在 coding 场景手里有三张底牌

通用对话记忆难做，是因为没有外部真值。coding 不一样。

① 世界是权威的

文件系统、git、测试结果就是当前态真值。记忆说"决定用 JWT"，grep 一下就知道做没做——陈旧决策污染大部分被外部 oracle 消解。

② 任务边界大半免费

commit、分支切换、测试由红转绿都是天然任务边界——issue/PR/bug 就是现成的分段单元，不用费劲推断。

③ 查询常是精确符号

函数名、路径、错误码、测试名——倒排索引在这类查询上是确定性的，零幻觉、零延迟、可审计。

所以 coding 域的记忆真正要回答的不是「现在是什么」——
是「为什么是这样」「什么试过且失败了」「我们的惯例是什么」。
这三类恰好全是原文比蒸馏好的负载。

第二幕 ·  核心主张

四条主张，整个设计立在这上面

  1. 显著性是查询条件化的写入时的取舍必错 → 不取舍，全留原文。
  2. 压缩的罪在删原件摘要只准做导航（决定读不读），不准做替代（代替原文被消费）。
  3. 权威分离「现在是什么」问世界（代码/git/测试）；「为什么这样、试过什么没成」问日志。拿日志推现状，是用副本对抗原件。
  4. 全量暴露不是上界日志里失败尝试和作废结论没有作废标记，必须裁剪；但裁剪依据只能是机械规则，不是"重要性"。
一句话 写入侧零 LLM：事件原文落库、按任务分段、机械索引；读取侧让 agent 自己把心智模型读出来。 系统里没有 memory 表、没有 summary 表，只有事实表加索引。

第三幕 ·  架构 · 事实层

最细粒度是事件，不是对话

别的系统
user_text / assistant_text
只有两列文本。工具世界被过滤两次——没有任何结构能表示「agent 做了 X」，这是 Dynamics-memory 最大的结构性障碍。
→
TASKLOG
role: user | assistant | tool | system
tool_call 与 tool_result 分两行存（时间不同各自可检索），call_id 配对；大结果不落 text 落 blob_ref。

为什么 tool 行是一等公民

agent 的行为不是它说了什么，是它读了什么文件、跑了什么命令、哪步报错了。砍掉 tool 行，剩下的"记忆"只是一份看不出做过什么的聊天记录。

为什么大结果落盘

读一个 5000 行文件，text 只存摘要行（路径、行数、头几行），原文落 blob——否则 FTS 会被单次文件读淹没。blob 支持按字节范围读回。

第三幕 ·  架构 · 分段

任务是服务单元，边界是推断产物

命中在事件级，服务在任务级——发现通道要细，服务单元要整。

边界来源，按可信度排序

  1. git commit / 分支切换最可信（boundary_src='git'）
  2. 测试由红转绿、文件突变、长间隔heuristic
  3. 用户显式说"好了/下一个"user

boundary_src 必须保留

边界是推断出来的、允许事后修订。原文是事实，边界只是索引——索引错了可以重建，这是本方案相对压缩方案的核心退路。

task_edges 里的 supersedes 边是"旧值新候选并排端出"那个病的解法：检索时自动排除被取代的任务。

承重墙存疑（如实标注） 检索的服务单元、切点、supersedes 全压在推断边界上。导入的 68 个推断任务没逐个人工审计——边界错了整层索引跟着错，目前只有机制测试，没有边界质量专项评估。

第四幕 ·  读路径

事件级命中，任务级服务

resume_task 不能退化成 search 的一种用法 状态重建要的是完整性和未闭合项，不是相关性——用 top-k 恢复状态，会恢复出一个有洞的心智模型，而 agent 不知道有洞。
第四幕 ·  读路径

起点建模，收口在验证门

任务起点（有预算的 K 轮）

  1. 并行广撒 3–5 个查询list_tasks + symbol_history + search_history
  2. 按结果收窄read_events / read_blob 补全
  3. 批量证伪把断言拿去撞世界
  4. 进执行循环midtask 继续可查，finish_warmup 可早停

验证门：收口必须撞世界

建模完成时，把心智模型里所有可被世界证伪的断言批量验证一次。日志说"认证走 JWT，在 auth/middleware.py" → grep 验。失败说明日志相对代码已过期，报给 agent，而不是让它带着错误前提开工。

零 LLM、一次性、可并行。coding 场景白送的外部验证器。

一个要防的过读倾向 agent 很容易过度阅读：K 和读取预算都要可配，停止条件要显式告知——你建的心智模型是为了回答什么。主动检索的额外开销在评估里单列，不摊进总数。
第四幕 ·  读路径 · 机械规则

成功给结果，失败给全过程

不对称裁剪（零 LLM）

成功路径的过程在代码里——代码就是它的产物，要细节读代码。失败路径在世界上不留痕迹，只有日志有——那才是日志不可替代的部分。所以成功的过程裁掉，失败的过程全留。

被取代的默认照样返回，强制带 currentValidity

被取代的那段恰是"当初为什么、后来为什么推翻"的所在。要防的不是看见旧结论，是把旧结论当现状——用标注解决，不用隐藏解决。显式 only_current=true 才排除，且返回 filteredOut 条数让调用方知道自己看的不是全部。

这条推翻了初版主张 初版写"被取代内容默认不出现在首次返回"——那等于把最该读的一段删了。依据：2607.08716 报 full-bank 全量暴露差 2.8 点，支持"要裁剪"，不支持"按有效性隐藏"。裁的是量，不是真值状态。
第四幕 ·  读路径 · 演进中

纯拉的实测暴露了一个洞：
模型不知道存在的东西不会去搜

首跑 C 臂 20 次记忆查询全部挤在 warmup，midtask 零查询——不是没东西可查，是执行中没有通道告诉它"你刚碰的文件有历史"。

→

[碎片 | task_58 · ev_1234 | 2026-08-03 | outcome:error | 已被取代] "试了 inline barrier，audit_chain 在超时边界漏掉未就绪探针 —— 因为 fence 在 timeout 分支没先排空队列"

碎片是调查起点不是背景知识：价值在携带可追的钩（ev_id、task_id、原话、"因为 Y"）。 排序零语义（error > 被取代决策 > 用户纠正）、必带解毒头、限量去重、标注未裁决。 推存在性线索，拉完整证据——agent 顺着钩自己拼出心智模型。

与被否决的 Dynamics recall.py 的区别 那个每轮注入的是给模型消化的语义块；这个注入的是给模型追查的原始证物。越过"机械匹配/只切不评/必带头"三条线就退化回去。
第五幕 ·  评估

记忆有没有用，不许自己说了算

同一前沿模型、同一仓库起始快照、同一组 coding 工具，只差上下文来源。

臂上下文来源角色
A 冷启动只有当前任务描述 + 仓库下界参照——它不是"基线"，只是地板
B 长上下文历史装得下就完整给；装不下机械降级成 B′不许拿人为残废的 B 去赢
C tasklog七个工具主动展开（K 轮预热 + midtask 续查）被测对象

判胜看任务，不看问答分

实际完成（独立验收逐条核对）> 返工次数 > 重复失败 > 过期假设。token/费用/耗时成本单列，不许合并成综合分。

防泄漏做不到，整组作废

严格按时间切分：第 N 个任务只见之前的历史。还有第 5 类"历史无关任务"故意保留——只测对自己有利的局，等于只找自己赢的局。

如实读法

C 与 A 检查结局相同，但多花 ~1.4× input、+50% 请求——检索开销没有换成正确率。B′ 连时序检查都没过：压到 49K 的历史基座反而比冷启差。三臂全卡 barrier_timeout 语义——可能是任务本身难点。

第六幕 ·  边界

诚实清单：现在哪里还漏

机制缺口

  • 向量通道未接入——三条互补通道定位写死了，最大未实现项；"倒排+FTS 不够"仍是 [假设]
  • outcome 维度缺失——数据有（343 个 error 事件），search_history 没有 outcome 过滤
  • 跨任务惯例无索引——"本 repo 一律先 lint"不在任何单任务里，需确定性计数索引

证据缺口

  • n=1 单任务——不能外推"记忆无用"，只能说明此探针切片上没收益
  • B′ 是偏弱对手——99%+ 事件被丢，长上下文真实实力没测到
  • 任务边界未审计——68 个推断任务，边界质量没有专项评估

演进中：线索式推

推碎片 + 拉原文的混合通道已定向，未实现——对照变量现成：C（纯拉） vs C′（推+拉），看 warmup 轮数 / midtask 查询 / 总 input / 检查结局。

未解矛盾

"心智模型 pin 缓存"若跨会话存续，压上"不允许任何形式持久化摘要"红线——除非明确定性为可重建缓存而非记忆。

尾声

记忆的职责不是替 LLM 记住答案，
是让 LLM 随时能回到证据。

写入零加工，所以没什么可错的；
索引可重建，所以错了也赔得起；
原文永远在，所以每句话都能被追着对。
